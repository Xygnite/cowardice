# Rigging Pixel Sprites

## Overview

Characters are cut-out rigs: the sprite is sliced into parts (legs, body, weapon, shield, head, and
optionally chest, lantern + glow, skirt strips), each on the full sprite canvas, hung on pivots and
animated by an AnimationPlayer. Everything is generated by `tools/rig_sprites.gd` from its `RIGS` table,
so **a rig is changed by editing `RIGS` and re-running the tool, never by editing `scenes/<name>.tscn`**
(the next run overwrites it). Sprites come from `tools/make_sprites.gd` the same way: edit `SPRITES`, re-run.

Pixel art rules the rig follows: whole-pixel moves (discrete keys), whole-number scaling (`SPRITE_SCALE`),
rotation only for short swings and tilts, frame swaps instead of rotation for anything long that sways,
and no bone deformation (Skeleton2D/Polygon2D smears pixels).

`G=./Godot_v4.7.2-stable_win64_console.exe`; if the version changed, `ls Godot_*_console.exe` finds it.

## Getting New Art In

Put the source in `art/reference/` (keep its file type; never re-save pixel art as jpg) and add a
`SPRITES` entry in `tools/make_sprites.gd`. Enemies face left: add `"flip": true` if the art faces right.

| Source | Entry | Notes |
|---|---|---|
| Painting / illustration | `{"src": "<name>", "out": "<name>", "h": 48}` | Shrunk to `h` px tall (normal enemies 44-50, big ones 60) and fitted into the shared palette. `.jpg` is assumed when `src` has no extension. |
| Already pixel art, blown up | `{"src": "<file.png>", "out": "<name>", "cell": 10.24}` | `cell` from `measure_cells.gd`. Read back one pixel per cell at **native size** (no `h`), snapped to the palette without changing it. |

- Pixel-art sources can't be resized without repainting. Check the size the tool prints: a figure
  over ~80 px tall towers over everyone (240+ screen px at `SPRITE_SCALE` 3). Ask the user before
  shrinking it through the `h` path instead, which blurs it.
- `measure_cells.gd` warns when the grid doesn't start at 0; crop that many pixels off the source first.
- `"pad": 2` keeps empty pixels around the figure. Add it when a lantern or cloth part sits at the
  figure's edge, or its sway frames get clipped.
- `make_sprites.gd` rewrites every sprite. Copy `assets/sprites/` to the scratchpad first and `cmp` after:
  the other sprites must be byte-identical unless you changed their entries; if they changed, re-rig all
  of them (`rig_sprites.gd` with no `--only`).
- `RIGS` coordinates are always read off the zoom of the finished sprite, after flip and pad.

## Adding or Fixing a Rig

1. **Zoom the sprite** (grid line every 5 px) and read the source in `art/reference/` to know what each
   blob of pixels is. Sprites listed with `"flip": true` are mirrored from their source.
2. **Add/edit the `RIGS` entry** (format documented above the table in `tools/rig_sprites.gd`;
   `plague_doctor` uses every optional part):
   - `facing`: 1 looks right (hero), -1 looks left (enemies). Lunges and flinches follow it. It describes
     the finished sprite, so a flipped enemy is still -1.
   - `body`: hip pivot. `legs_top`: first row of legs that stay still; sprite height if it has no legs.
   - `weapon` / `shield` / `head` are optional, each an `outline` (polygon claiming pixels; checked in
     that order, so a weapon crossing the body is claimed before the body) and a `pivot`:
     weapon pivot = the gripping hand, shield = its grip, head = the neck.
   - `swing` = `[wind-up, strike]` radians. Godot rotation is clockwise-positive (y points down):
     a blade hanging down-right lifts with a negative wind-up; one hanging down-left lifts with a positive one.
   - No shield means no `block` animation; that is fine.
   - `chest` (`outline`, `pivot` on the belt): torso above the belt, with the pauldrons and the arms that
     hang from it. It rises 1 px to breathe and carries head, weapon, shield and lantern.
   - `lantern` (`outline`, `pivot` = top of the hook or chain in the hand, `glow` = outline around the lit
     pixels): anything that hangs and swings (lantern, censer, bell, pendant). It sways by sheared frames,
     so it never strikes: a prop that hits is the `weapon`. Keep the hand out of its outline. `glow` only
     exists on the lantern. A hanging prop that is also the attack (a flail, a censer he hits with) is the
     `weapon`: the hit matters more than the sway and flicker, which are lost. Tell the user that trade.
   - `skirt`: a list of outlines, one per loose strip (tatters, coat tails, cape ends): only cloth that
     hangs free, a few px wide, from where it leaves the body down to its tip. Each strip shifts 1 px.
3. **Run the tool with `--preview`**, then zoom each part. Each part should hold the whole object and
   nothing else; tighten outlines and re-run until they do (a stray column of coat in the weapon is common).
4. **Import**, then **render the pose sheet** and read it: wind-up raises the weapon, strike lands
   forward of the body, the rig lunges toward its target, hurt flashes red and recoils away.
5. **Wire it in** if new: an enemy type in `scripts/combat.gd` `TYPES` gets `"sprite": "<name>"` and a place
   in a `FIGHTS` row (that changes difficulty: tell the user which slot you used).
   `scripts/combat_screen.gd` then builds the rig and plays its moves. A sprite with no rig scene breaks
   that screen, so rig every sprite an enemy type uses.
6. **Run both tests**. Add the fight to `FIGHTS` in `tests/test_fight_flow.gd` if it uses a new rigged enemy.

## Frame-by-Frame Versions (pxl)

Every rig also has a baked frame version that the game prefers (`scenes/<name>_frames.tscn`, picked up by
`_add_rig` in `scripts/combat_screen.gd`). It is drawn by the pxl skill (`.claude/skills/pxl-pixel-art`)
from the rig's own parts, so re-cut the rig first, then:

1. `"$G" --headless --path . -s tools/pxl_parts.gd -- <name>` writes `art/pxl/<name>_parts.px.js` (palette, parts, RIG).
2. `art/pxl/<name>.px.js` includes it and `lib.px.js`, then calls `standard("<name>", overrides)`: idle, attack
   (impact exactly 0.2 s in, for `STRIKE_DELAY`), block (with a shield) and hurt, all from RIG. Fix bad cuts there:
   `claim(to, from, rect)` moves pixels between parts (`to` null deletes them), `RIG.under` paints what the
   weapon hid, `RIG.anchored` keeps a post or gallows still, `RIG.head.still` stops a head opening its hole.
3. `node .claude/skills/pxl-pixel-art/bin/pxl.js build art/pxl/<name>.px.js`, read `art/pxl/out/_preview/<name>_*.png`.
4. Copy `art/pxl/out/<name>_frames.png` and `.json` to `assets/sprites/`, run
   `"$G" --headless --path . -s tools/frames_scene.gd -- <name>`, then `--import`.

The pose sheet only reads cut-out rigs; check frames in the pxl previews.

## Common Mistakes

| Symptom | Cause / fix |
|---|---|
| New parts load as missing textures | Skipped `--import` after the tool wrote new PNGs. |
| Hand edits to a rig vanished | Scenes are generated; put the change in `RIGS`. |
| Pixel-art sprite looks mushy or has doubled pixels | Wrong `cell`, or the grid is offset; re-run `measure_cells.gd`. Never put pixel art through the `h` path. |
| Weapon swings the wrong way / into the body | `swing` sign; see the rotation rule above. |
| Raised weapon disappears against the body | Same colours as the chest behind it; try a smaller wind-up. The blow lands 0.2 s in (`STRIKE_DELAY`), so a longer wind-up needs a code change. |
| Part rotates around the wrong point | `pivot` not on the joint; re-read it off the zoom. |
| Background shows behind a moving weapon or shield | Its outline is too wide. Holes are only patched where the part covered the body, from the nearest body pixel in the same row or column. |
| Background flashes behind a tilting head | Expected: head holes are not patched (patching smears). Keep head tilts small. |
| Lantern cut off on its outer sway frames | It sits at the canvas edge: add `"pad"` to its `SPRITES` entry and re-read every coordinate (they shift by the pad). |
| Whole cape slides sideways | Skirt outline covers attached cloth; keep strips to the loose ends. |
| Flat background colour left between an arm and the body (dark backgrounds only) | The edge fill can't reach enclosed pockets. `make_sprites.gd -- --pockets` lists them; check each against the reference and add real ones to the entry's `"holes"`. |
| Sprite full of see-through holes | Not a rig problem: `tools/make_sprites.gd` cut pixels close to the background colour. Fix the cutout, regenerate sprites, then re-run the rig tool. |
| Pose sheet is blank white | Ran it with `--headless`; it needs a renderer. |
| Rig jitters by sub-pixels | Position and frame tracks must be discrete (`update: 1`); the tool's `_track(..., true)` does that. |
